# Правила для художника — PM VR v3

У Blender ці правила відкриваються кнопкою `?`: Artist Rules, Runtime Names,
After Bake. Основа — погоджені правила платформи, розділ 3.2, та PC-специфікація,
частина II, розділ 8. Поточний спільний контракт у папці Sync має пріоритет.

## Підготовка

- Перший UV-канал `UVMap`, другий `SimpleBake`; назви не змінювати.
- Усе, що впливає на бейк, — у Source Root. Освітлення кожного look — у власній колекції.
- У Project Settings додайте потрібні look-и з колекцією світла та World: один Default, назви одним словом латиницею, без `_`, відмінні від типів шарів і назв зон.
- Камери проб будь-якого типу — у налаштованій колекції, включно з вкладеними. Призначте їх у Runtime.
- PBR: один Principled BSDF на слот. Alpha: Principled Alpha або мікс із Transparent.
- Island Padding збігається з пакувальником. Рекомендований TD: ~10 px/см зблизька; стіни/підлога5–7; великі стелі~4.
- Новий проєкт створює власну папку PMVR. Старий зберігає свої папки.

## Імена Runtime

| Ім’я | Тип і призначення |
|---|---|
| `StartPosition` | Рівно один Empty на підлозі. +Y — напрямок погляду, поворот лише Z. |
| `Navmesh*` | Обов’язковий меш ходіння й телепортації. |
| `Probe_<Name>` | Хоча б одна камера в колекції проб; експортується як Empty. Для кожного look потрібен відповідний EXR. |
| `Skybox[_<Zone>][_<Look>]` | Меш неба; origin у центрі. У кожному look потрібне небо за замовчуванням. |
| `Zone_<Name>` | Меш-коробка охоплює підлогу з запасом вниз; поворот лише Z. Ім’я зони не збігається з look. |
| `SkyPoint_<Zone>` | Empty задає позицію центра неба для зони. |
| `Hotspot_<Name>` | Empty телепортації на підлозі, +Y вперед; `title`, `order`; прев’ю `hotspots/<EmptyName>.jpg`. |
| `InfoButton_<Name>`, `InfoPanel_<Name>` | Empty кнопки й панелі; позиції/повороти; текст `info/<Name>.md`. |
| `SFX_<Name>` | Empty точкового звуку. Sphere size1, масштаб — радіус; `volume`, `title`. |
| `Ambience_<Name>` | Empty фонового звуку. Позиція визначає зону, поворот Z — напрямок запису; `volume`, `title`. |
| `Music_Source`, `Music_Button`, `Music_Panel` | Empty джерела й інтерфейсу музики. Зона джерела — за положенням; `volume`. |
| `Video_<Name>` | Меш відео `video/<Name>.mov` або `.mp4`; UV й opacity з матеріалу. |
| `Clock_<Name>` | Меш цифр годинника. Перший UV0–1 без перевертання; колір цифр — Base Color. |
| `Collision*` | Невидимий меш звукових колізій. |
| `Inspect_<Name>` | Empty у центрі предмета. Потрібні `inspect/<Name>.usdz` та `<Name>.md`. |
| матеріал `RK_<Shader>` | На меші Runtime: шейдер бібліотеки застосунку, наприклад `RK_Water`; ім’я меша довільне. |
| `Teleport*`, `<Prefix>_StartPosition` | Зарезервовані для вебу/iOS; зберігати. |

Номер `.001` перетворюється в USD на `_001` і не змінює роль. Невідомі імена
дають попередження, аддон їх не перейменовує й не видаляє. Zone/Navmesh/Collision
тимчасово приховані під час бейку та рендера проб; їхня видимість відновлюється,
а експорт зберігає службові меші.

## Що робити після змін

Експорт запеченого об’єкта бере згенеровану копію. `Ready` означає, що результат
існує; це не автоматична перевірка нових змін у джерелі.

**Перезапекти юніт у всіх look-ах:** геометрія, модифікатори, будь-який UV,
позиція, поворот, масштаб або запечений матеріал змінилися. Те саме стосується
перемикання PBR Diffuse Only для PBR-юнітів.

| Зміна складу | Дії |
|---|---|
| Додано об’єкт у спільний юніт | Перепакувати весь SimpleBake разом, перезапекти. |
| Перенесено об’єкт між юнітами | Перепакувати й перезапекти обидва юніти. |
| Ctrl+J оригіналів | Перепакувати результат; перезапекти також юніт, з якого пішов об’єкт. Порожній — Remove Empty Units. |
| P / дублікат | Нова частина або копія потребує призначення юніта, пакування та бейку. |
| Видалення | Експорт пропускає видалений об’єкт; перебейк спільного атласу за бажанням. Порожній — Remove Empty Units. |

**Без перебейку:** імена об’єктів/мешів/матеріалів, порядок шарів, видимість,
резолюція експорту юніта (вниз або вгору до запеченого розміру). Нові об’єкти
можна додавати, але вони потребують власного Setup перед експортом.

Властивості оригіналу `title`, `order`, `volume`, `opacity`, `brightness`,
`emissiveIntensity` доходять при наступному експорті, без перебейку.
Glass, Emissive та Runtime експортуються з оригіналів — їхні зміни потребують
повторного експорту. Властивість сцени `reflectionIntensity` записується в опис
експорту (за замовчуванням1).

**Світло або об’єкти, що його затінюють:** перебейк зачеплених юнітів у цьому
look і повторний рендер проб.

Послідовність: оригінал → пакування SimpleBake → склад у Setup → черга → усі
потрібні look-и → бейк → експорт шару в кожному look. Якщо змінювалось світло,
також проби. Перейменований шар отримує новий файл; старий більше не входить
в опис експорту, але лишається на диску для ручного прибирання.

Не редагуйте `PMVR_GENERATED`, `PMVR_WORK` і не об’єднуйте їхні копії з джерелами.

## PBR і проби

PBR Diffuse Only за замовчуванням вимкнений. Mac підтвердив готовність нового
шейдера; режим можна випробувати в тестовому Blender. Старі атласи автоматично
не перетворюються. Спершу перевірте один PBR-юніт, потім свідомо перебейкайте
потрібні PBR-юніти в кожному look. Усі інші збережені бейки лишаються.

Проби: усі камери × усі look-и, незалежно від галочок Bake. Позиція з камери,
орієнтація світова (+Y вперед, Z вгору), типова панорама1024×512 RGB Half ZIP.
EXR — у Sync/probes, JPEG того самого рендера — локально в PMVR/ProbePreviews.
Картинки місць/варіантів600×440 і проєкту960×1200 робить власник; аддон їх не перезаписує.

## Зручні інструменти

У **Setup** є окремі блоки **Viewport**, **Runtime** та **Object Properties**.
Старі робочі папки можна один раз впорядкувати через **Project Settings →
Organize Local Files**. Аддон перевіряє копії файлів, оновлює посилання, зберігає
проєкт, а попередні папки й `.blend` залишає в `PMVR/Backups`. Перебейк не
потрібен. Це не відбувається автоматично при відкритті; сторонні папки, Sync і
вихідні textures/assets не переносяться. Резервний `.blend` відновлюється на
колишнє місце разом зі старими папками через журнал, а не відкривається прямо
з Backups. Нові Lightmaps/збережені через Optimize текстури — в `PMVR/`.
Створення/іменування Runtime й редагування властивостей є лише в Setup.
**Object Properties** показує лише властивості для вибраного шару чи Runtime-ролі.
Якщо вибрана запечена копія, редагується вказаний оригінал. Для відсутнього
параметра є **Add**; наявний редагується прямо в полі. Додається лише активному
оригіналу; наявне значення та вибір об’єктів зберігаються. Режимів Set/Inherit,
Bulk, копіювання чи видалення в цьому меню немає. Відсутній параметр далі бере
значення з матеріалу або правил платформи. Початкове значення Add — з матеріалу,
якщо його можна однозначно прочитати; інакше числові множники/Opacity/Volume
починаються з1, Order — з0, Title — із запропонованої назви. `title` для SFX — підпис
групи звуку в мікшері, наприклад Street; задавати його необов’язково.

У Setup списки шарів і об’єктів/юнітів відкриті постійно. Viewport, Runtime та
Material Variants спочатку згорнуті; Object Properties відкритий, але його теж
можна згорнути. У Bake черга, вибір look-ів для бейку й запуск/скасування завжди
на виду. Bake Scenarios з колекціями/налаштуваннями, Probes і Viewport — згорнуті
під чергою. Стрілка в заголовку розгортає блок; вибір пам’ятає сам sidebar.

**Create Runtime** — один діалог для точок, зон і камер проб. Для наявного
меша — **Set Runtime role / name**. Кінцеве ім’я видно до застосування;
тип об’єкта, дублікати імена та зони перевіряються. Для неба конкретного look
задається також відповідна lighting collection; спільне небо лежить поза ними.
**Check Runtime** показує проблеми та очікувані файли; клік на назві вибирає
об’єкт. Перевірку повноти експорту й розташування завершує AM.

**Sources / Generated** взаємовиключні; **Both** — свідомий вибір для порівняння.
Після черги видно лише успішні результати з **Last queue only**. Якщо успішних
результатів немає, старі не показуються як нові; фільтр можна вимкнути.
Він стосується тільки вьюпорту. Клік на юніті вибирає його видимі об’єкти,
лупа знаходить їх у вьюпорті. У матеріалах копій активна запечена Beauty,
включно з уже наявними бейками; оригінальні шейдери лишаються авторськими.

У Glass, Emissive та Runtime список об’єктів клікабельний і прокручується;
усі назви впорядковані за алфавітом, пошук відкривається стрілкою під списком.
Клік показує Sources та вибирає відповідний оригінал у сцені. Вибір у сцені
підсвічує рядок у списку; перейменування чи видалення не підміняє його ціль.
